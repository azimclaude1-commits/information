# AlphaPulse prototype — agent notes

React 19 + Vite 8 + Tailwind CSS v4 single-page prototype (CFD / crypto **demo-trading** terminal, AICoin-style features). Hash routing lives in `src/App.tsx` (`#home`, `#trade` = the single CFD交易 desk that also lists crypto, `#flash`, `#headlines`, `#diagnose/<tab>`, `#dividends[/dividends]`, `#news`, `#live`, `#withdraw`). Legacy hashes resolve through `NAV_ALIASES` (`#market` / `#futures` → `#trade`, `#market_overview` → `#home`). Below `lg` the top nav is a fixed bottom tab bar (`MOBILE_TABS`: 首页 / 交易 / AI诊股 / 资讯 / 账户) and `#news` renders `NewsHubView` (快讯 / 要闻 / 资讯日历); `ACTIVE_TAB_OF` decides which tab is highlighted for folded routes. The desktop nav and pages are unchanged above `lg`.

## Commands
- Dev server: `npm run dev` (Express + Vite middleware on port 3000, hard-coded in `server.ts`).
  If port 3000 is taken, preview the frontend only with `npx vite --port 5188 --strictPort` (`/api/diagnose` falls back to local demo data).
- Type check: `npm run lint` (`tsc --noEmit`) — must stay at 0 errors. `tsconfig.json` has no `include`, so any extra source folder dropped into the project root (e.g. the `qwen3.8flash/` reference prototype) is type-checked too and breaks `lint`; keep such folders outside the project or exclude them.
- Production build: `npm run build` (the >500 kB chunk warning is pre-existing).

## Demo trading (simulation only — no deposits / withdrawals)
- Engine: `src/components/demoTrading.ts` → `useDemoTrading()` is called once in `App` and passed down. It owns the shared demo balances (`cash` = funding wallet / `stock` = the one trading account / `reward` = check-in & rating bonuses), positions, limit orders, closed-trade history and the funding ledger, all persisted in `localStorage` under `alphapulse.demo.*.v1` (balances live under `alphapulse.demo.accounts.v2` after the perpetual wallet was folded in; the asset page's "重置模拟账户" restores the seed data). `CHECK_IN_REWARD_USDT` / `RATING_REWARD_USDT` / `REWARD_WITHDRAW_FEE_USDT` are the fixed reward amounts; `creditReward()` and `withdrawReward()` are the only flows that touch the reward account.
- Accounting: one trading account, margin split by currency so the two market views never double-count — `ACCOUNT_FOR.cfd` collateralises with `stock.USD`, `ACCOUNT_FOR.perp` with `stock.USDT`; both settle into `stock`. Equity = balance + unrealized; free margin = equity − used − frozen (pending orders). Realized P&L settles into the account and writes a `TS-` ledger row. Contract sizes: stocks/commodities 100, indices 10, forex 10,000 per lot; perps are quoted in coin units. TP / SL / liquidation and limit fills are checked on every price tick.
- UI: `TradingWorkspace` = `MarketTerminal` + `OrderTicket` + `PositionsPanel`. Desktop retains the watchlist / chart / details columns, with the ticket in `MarketDetails` and positions below the chart. Below 1024px, `MobileTradingDesk` supplies a quote header, instrument picker sheet, and 交易 / 图表 / 数据 / 信息 / Agent策略 tabs. The compact ticket and expanded positions panel sit together under 交易; this panel stays mounted to preserve drafts when switching tabs. `mobileTrading.css` uses terminal theme tokens. `MarketChart`'s `mobile` prop starts with 40 candles and volume only, and fits the drawing to the available height; all indicators remain selectable. One desk lists CFD and crypto: `mode` comes from `marketOf(instrument)`, so ticket, quotes and positions switch account with the symbol. The radio icon opens `livePane`. `MarketChart` accepts `priceLines` for entry / TP / SL / liquidation / limit overlays.
- 特色指标 (`SignatureIndicators.tsx` + `signatureMath.ts` + `signature.css`): ports of the product team's three Pine Script indicators — 金眼主图 (BBI Box System: BBI, 30-bar safe line, box top/bottom, B/S + ▲/▼ with the zero-overlap label manager), 三合一副图 (MACD·KDJ·RSI24 on one axis; DIF multiplier adapts to price instead of the script's fixed ×150 so FX/BTC both fit; four-colour histogram; triple-bottom/top checklists) and 背离副图 (OBV-MACD normalised to ±50 over 100 bars + MACD/KDJ/RSI/DMI divergence bubbles). Below the trading chart (desktop after `</main>` of `MarketTerminal`, phone inside the 图表 pane under `MarketChart`) only the `SignatureGate` entry is rendered; the three panes open in a dialog after an AI analysis (see Membership). Uses the same `makeCandles` series/period as the chart; the three panes share one crosshair. Keep the math file name distinct from the component (Windows is case-insensitive).

- Asset home (`AssetHome.tsx`, `overview`) stays minimal: total-assets card (eye toggle persisted in `alphapulse.assets.hidden.v1`, 资产明细 link), quick actions 领模拟金 / 划转 / 奖励提现 / 资金记录, and tabs 交易账户 / 资金账户 / 奖励账户 with one compact card each. ## Membership & AI quota (`src/components/membership/`)
- Model (`membershipState.ts`, pure, covered by `npm run test:membership`): `PLANS` = 免费版 3 / 普通会员 $10 · 20 / 高级会员 $30 · 80 / 至尊会员 $99 · 300 AI analyses per day. Every model-backed feature draws from ONE shared daily pool (`AiFeature`: `diagnose` AI诊股, `insight` AI分析 = desk AI 解读 + news AI 摘要 + Ace智搜 questions, `kline` K线分析 (charged per confirmed crop, see K线分析), `signature` 特色指标). The pool resets at 00:00 UTC+8 (`dayKey` / `nextReset`). Reopening the same key on the same day is free (`unlocked`); "重新生成 / 重新诊断 / 继续提问" pass `force` and charge again. Monthly periods (30 days): same tier renews from the current expiry, a higher tier starts now and credits the unused days, lower tiers are not sold while a plan is active. Ace 深度思考 + the shorter simulated wait (`delay`) start at `DEEP_TIER` (premium).
- Store: `useMembershipStore(lang, toast)` is called once in App (like `useLive`) and shared through `MembershipProvider`; components use `useMembership()` → `request(feature, key, label, {force})` (returns false and opens the upgrade sheet when the quota is gone), `requireTier(tier, label)`, `isUnlocked(key)`, `open(path)` (navigates to `#vip/<path>` and remembers the page to return to). Persisted in `alphapulse.membership.v1` and synced across tabs. Orders are created `processing` and settle after ~2.4 s (paid → plan activates; `failReason` → failed, nothing charged).
- UI: `AiLock` blurs an AI result behind a "消耗 1 次" card (used by AI诊股 and its 四维研报 tab); `QuotaPill` shows 今日剩余; `TierBadge`, `.mb-ava.is-<tier>` avatar ring (header, AccountPanel, member centre); `MemberStrip` on the asset home. 特色指标 no longer renders inline: `SignatureGate.tsx` shows blurred previews below the chart and opens `SignatureIndicators` (`embedded` mode adds the AI 结论 block) in a full `Sheet` after the analysis (per symbol + period per day).
- Route `#vip` (`MembershipView.tsx`, folded into the 账户 tab): `#vip` 会员中心 (status + ring, per-feature usage, plan cards, 权益对比, today's records, auto-renew switch, saved cards, FAQ, 重置会员演示数据), `#vip/checkout/<tier>` 确认订单 (tier switch, 连续包月, method list, fee breakdown, terms sheet, method-specific pay button; phone uses a fixed pay bar above the tab bar), `#vip/order/<id>` 支付详情 (processing timeline → success with activation card / failure with reason, order + fee rows, receipt sheet), `#vip/orders`.
- Payment invocation (`PaymentSheets.tsx`): Apple Pay and Google Pay are system-styled overlays (`pay-sys`, z-index 140) with card choosers and confirm animations (side-button double-click / Face ID on touch devices, Touch ID on desktop); the card form is a `Sheet` with brand detection, Luhn/expiry/CVC validation, billing country (`CountrySheet`), save-card and a 3-D Secure step (`DigitInput` + sandbox code). The sandbox only accepts `TEST_CARDS` (success / 3DS / insufficient funds / declined) so real card numbers are never typed in; only brand + last4 are stored. No payment provider is contacted.

## K线分析 (`src/components/kline/`)
- Model (`klineAnalysis.ts`, pure, `npm run test:kline`): `analyseKline(series, from, to, focus?)` reads a cropped candle range — regression trend, R2/R1/pivot/S1/S2 from swing points, up to 4 recent patterns (engulfing, hammer, shooting star, doji, three bars, double bottom/top, range breakout/breakdown), MA5/10/20 order, MACD cross, RSI14, KDJ, volume ratio, a 0–100 score → 偏多/偏空/震荡, and long/short plans (entry / stop / target / R:R). Results are structured data; text is composed in the UI so records follow the language switch. Indicators warm up on bars before the selection.
- Records: `KlineRecord` (selected bars + result + `source: "desk" | "ace"`) persisted in `alphapulse.kline.v1` via `useSavedState` (`useKlineRecords()`), newest first, max 40. The trading desk and Ace智搜 read the same list — never keep a separate history.
- UI (`KlineAnalysis.tsx` + `kline.css`): `KlineCropper` (portal, z-index 120, below sheets) pre-selects the candles that were on screen (`MarketChart`'s `onView` reports `{symbol, period, start, end}`), shows extra earlier candles dimmed, and has a crop box you can move, resize by edges/corners (snaps to candles, min 5) or redraw by dragging on the dimmed area; narrowing it vertically adds a 关注价格 band. `KlineFlow` = crop → `ConfirmSheet` (symbol / period / count / time / band + quota) → loading steps → `KlineResultSheet` (`KlineReport`: verdict + score, snapshot with R1/S1/pivot and pattern dots, overview stats, patterns, indicators, level ladder, two plan cards with 按此计划做多/做空). Confirming charges one `kline` analysis keyed by symbol + period + time span (+ band); the same selection reopens free the same day. The record is saved before the loading animation.
- Entry points: phone desk tab `K线分析` (6th tab in `MobileTradingDesk`; opens the crop page and shows a start card + `KlineHistory` with 当前品种/全部 filter), desktop quote header button beside AI 解读 (`MarketTerminal`, uses the first chart's view; 全部分析记录 goes to `#diagnose/ace/kline`), and Ace智搜 → K线分析 (`KlineWorkspace`: symbol/period picker, shared records list, selected report inline; the question composer is hidden on this topic). Plan buttons go through `onTrade` (desk: switch symbol + ticket side; Ace: App's quick-trade).

## Design system (keep new UI consistent)
- Tokens: CSS variables `--ui-*` in `src/index.css` (`:root` + `.dark`). They are exposed to Tailwind via `@theme inline`, so prefer `text-ink / text-ink-2 / text-ink-3`, `bg-surface / bg-surface-2 / bg-surface-3`, `border-line`, `text-brand / bg-brand-soft`, `text-up / text-down / bg-up-soft / bg-down-soft` over hard-coded hex + `dark:` pairs.
- Shared primitives (`@layer components` in `src/index.css`): `ui-page`, `ui-subnav`, `ui-page-head`, `ui-card`, `ui-card-head`, `ui-tabs` + `ui-tab` (`aria-selected`), `ui-seg` (`aria-pressed`), `ui-chip` (`aria-pressed`), `ui-btn` / `ui-btn-primary` / `ui-btn-soft`, `ui-input`, `ui-table`, `ui-badge-*`.
- `news.css` / `market.css` / `research.css` are unlayered and map their own variables (`--n-*`, `--panel`…) onto the `--ui-*` tokens; unlayered rules beat `@layer` rules, so put overrides that must win over them outside `@layer`.
- Inside `.market-terminal`, generic rules restyle every `button` (hover, `.active`); Tailwind utilities lose to them. Style terminal components with classes in `market.css` scoped as `.market-terminal .x`, and use `aria-pressed` / `aria-selected` instead of an `active` class. Trading styles live at the end of `market.css`.
- Fonts are self-hosted (`@fontsource-variable/inter`, imported in `src/main.tsx`); Google Fonts is not used (blocked in mainland China). `font-mono` is remapped to tabular Inter for figures; real code uses `--font-code`.
- Dark mode: `App` toggles `.dark` on `<html>`; the sticky chrome height is exposed as `--app-header-h` (112px below `lg` = 56px bar + 56px phone tab bar, 88px from `lg` with desktop nav + ticker) for full-height layouts. `--app-tabbar-h` is the phone tab bar height (0 from `lg`); `main` carries `pb-[var(--app-tabbar-h)]` so content clears the fixed bar.
- Avoid px-based arbitrary breakpoints like `min-[1400px]:` (they sort before rem breakpoints in Tailwind v4 and get overridden); add a `--breakpoint-*` theme variable instead (`xs` = 380px exists).

### Livestream engagement and replay extensions
- `liveExperience.ts` extends `alphapulse.live.v1` with per-room strategies and revisions, Q&A, polls/quizzes, recording/replay drafts, chapters, private notes, moderation, series/events, notifications and analytics. Legacy state migrates without resetting wallets/messages; legacy position sharing is cleared until consent is renewed.
- `LiveRoomTrade` places orders through the existing `demo.placeOrder` engine. On phones the order sheet slides up over the full-screen video. Strategy parameters are editable; expired/ended strategies cannot submit. Full-desk navigation retains a floating live player.
- `LiveStrategies`, `LiveEngagement`, `LiveReplay`, `LivePrograms` and `LiveStudioTools` expose independent viewer and creator controls. Room data is shared; viewer pages never render creator controls. Moderators may pin/mute/delete chat, but cannot change broadcast settings or publish strategies.
- Q&A supports upvotes, one on-screen question, answers and duplicate merging. Polls accept one response per viewer; quiz explanations appear after closure. Slow mode applies to chat and existing keyword/mute restrictions apply to questions.
- Recording is a prototype flag over the bundled video. Ending a room produces an unpublished replay draft, closes polls/strategies and revokes sharing. A reviewed recap is required before publication. Public replays appear in catalogs; unlisted replays open by link; unpublished recordings are gated in the viewer shell. Ended sessions cannot be restarted in the studio UI.
- `useRoomExperience` counts entries and visible-tab watch time. Strategy clicks and successful in-room paper orders update analytics. Existing room metrics are seed data; subsequent interactions are recorded locally. These are prototype counters, not production audience measurement.
- Reminders and notices are local in-app events while the app is open; no browser push, email, background scheduler or external analytics service is called. Follows, host notifications and program subscriptions are separate settings.
- The session assistant assembles existing chapter notes, host strategies and answered questions with source references. It does not transcribe audio or call an AI model. Creators can generate, edit and review recap drafts before publishing. Notes/progress are for the single local viewer identity.
- Position-sharing consent chooses new positions since joining or all paper positions. Leaving the room clears sharing unless continuing via the floating player; closing the floating player also clears it. No real orders, payments or account balance transfers are added.
- Styles for the additions live in `liveExperience.css`, using `--ui-*` tokens. Both route shells load them. Regression tests include migration, strategy lifecycle, Q&A, voting deadlines, notifications, publication review, moderation, sharing and analytics.

## News community
- `CommunityProvider` wraps App and shares public profiles, comments and following across flash news, headlines and livestream chat. `NewsComments` is collapsed by default and shows the actual comment count; expanded threads support replies, likes, newest/top sorting and deletion of the current viewer's own comments. Lists have bounded scroll areas and pagination.
- Comments persist in `alphapulse.community.v1`, migrate the previous `news.comments` data and synchronize through storage events. Authors have stable `author:<name>` IDs; the single following list remains in `alphapulse.live.v1`, with a one-time migration from `articles.following`. Never create a separate news follow list.
- Avatar clicks open a public profile with news/comment/live-chat history and public live/upcoming/published replay sessions. Unpublished/unlisted replays, wallet data and private notes are excluded. AccountPanel's 我的关注 entry supports search, profile navigation and unfollowing.
- `FollowingPanel` keeps a large fixed-height shell for populated, empty and filtered lists. Focusing the search field opens a dropdown with existing hosts/authors and searches the local profile directory; it is not a remote celebrity directory. The search, selected group and page remain when returning from a profile. Follow groups and one-group-per-person assignments persist in `alphapulse.community.v1`; create/rename/delete do not alter follow relationships. Deleting a group moves members to Ungrouped; unfollowed users retain their assignment if followed again, and group counts include only currently followed users.
- This remains a single-browser prototype: no real user directory, external social posting or backend moderation is connected. UI copy stays product-like. Reference interaction model: https://www.binance.com/en/support/faq/detail/a6dd93f996cb42a897651acfa19a98d6 . Verify with `npm run test:community`, `npm run test:live`, `npm run lint`, and `npm run build`.
